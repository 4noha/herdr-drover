# セミオート続行 判定ルールの変更履歴

`judge.go` の `RulesVersion` と対応。**ルール（正規表現・順序・見る範囲）を変えたら版を
上げ、ここに「何の事例を根拠に、何を、どう変えたか」を書く。** 事例はローカルの
`~/.herdr-drover/autocontinue/cases.jsonl`（判定ごとの材料と結果、停止後の人の反応）から
`herdr-drover auto cases export <id>` で `testdata/judge_cases.json` へ持ち込み、
`TestJudgeCorpus` が全体整合性を固定する（1 件直して別の 1 件を壊さない）。

判定器（LLM）のプロンプト変更も同じ扱い（版を上げる）。

## v4 — 2026-10-29（人への依頼は疑問符なしでも止める・判定器は 3 票の多数決）

- 根拠: コーパス `np1-sd-eject-imperative` / `np1-sd-insert-or-else`（ユーザー報告）。PioneerNP1
  の opencode が「SD を回収します: 1. 電源を切る 2. SD を抜いて Mac に挿す 3. 『挿した』と
  教えてください」と**命令形の箇条書き**で止まったが、v3 の人待ちルールは疑問文（末尾「？」）
  にしか当たらず判定器へ回り、判定器が CONTINUE → 「つづけて」を 2 回入れて別作業へ逸れた。
- 変更:
  - 認証情報・不可逆操作の承認・実機操作の依頼は**疑問符が無くても**止める。見る範囲は
    末尾のブロック（最後の空行より後ろ・最大 6 行・括弧書き除く）＝箇条書きの依頼を
    名詞＋依頼動詞の組として見る。実機名詞に SD／USB／カード／抜いて／挿して／装着／本体を
    を追加、依頼動詞に「教えて／知らせて」を追加。
  - 「続けますか？」の続行判定は従来どおり疑問文のときだけ（実機依頼が同じブロックにあれば
    そちらが先に当たる）。
  - 判定器は **3 回並列の多数決**（`judge_votes`、既定 3）。v3 の live 評価で完了報告が
    DONE/CONTINUE に揺れたため。過半数なしは停止側。source は `llm:2/3` のように票を残す。
  - 判定器を **hermetic** に: `--setting-sources ""`＋`--exclude-dynamic-system-prompt-sections`。
    揺れの正体は乱数ではなく **cwd とユーザー設定への依存**だった（同じ完了報告が /tmp では
    3 票とも CONTINUE、/var/folders では DONE、「HOLD」と答える票も。設定を読ませないと
    cwd に依らず DONE）。多数決は残す（きわどい事例の保険）。

## v3 — 2026-10-29（判定器プロンプトの DONE 定義を明確化）

- 根拠: コーパスの live 評価（`HERDR_DROVER_LIVE_JUDGE=1`）で `completion-report`（完了報告）が
  午前は DONE、午後は CONTINUE に揺れた。`token-term-normal-question` は HUMAN と判定され、
  「どの環境で検証するか」は人にしか決められない要件なので期待側を human に改めた。
- 変更: 判定器を `claude -p` の**既定システムプロンプト（コーディングエージェント役）から
  分類器役の `--system-prompt` に差し替え**（既定役のままだと完了報告を few-shot で DONE と
  示しても 3 回とも CONTINUE＝「作業を続ける」側に寄る。差し替え後は 3 回とも DONE）。
  `--no-session-persistence` で判定ごとの transcript を残さない。判定器の出力は**最後の**
  一致語を採る（説明付き回答の先頭一致で誤読しない）。
  併せて DONE を「完了報告で、残課題・問い・失敗の記載が無ければ DONE。仕事を作らない」と
  明記し、コーパス由来の few-shot（DONE/CONTINUE/HUMAN 各 2 例）を追加。
  `opencode-pytest-missing` は午前 HUMAN・午後 CONTINUE と揺れたが、方針（人にしか出来ない
  ことだけ止める）では自分で pytest を入れられるので期待を continue にし few-shot に採用。
  ルール層は変更なし。
- 併せて「？」の後ろに括弧書きが付く発話（`grant-continue-or-stop`）で疑問文判定が外れていた
  のを、末尾の括弧書きを除いてから判定するよう修正（v2 の仕様の穴）。

## v2 — 2026-10-29（人待ちは最後の一文だけ・「続けますか？」は続行）

- 根拠: コーパス `gts-20261029-secret-continue`。opencode（gts）が「…オフライン解析で
  進められます。続けますか？」で止まり、v1 は直前 400 文字の本文中の技術用語 "secret" に
  反応して `human-only-question` で停止した（14:46:50）。直前 2 回は正しく続行していた。
- 変更:
  - 人待ちの判定は**最後の一文**（最後の文末記号より後ろ）だけを見る。
  - 人待ちは「名詞＋依頼動詞」の組で判定する 3 種に分割: `asks-credential`（認証情報の
    提示依頼）／`asks-irreversible`（本番・デプロイ・push・削除・課金などの承認依頼）／
    `asks-physical`（実機・電源・ケーブル操作の依頼）。
  - `asks-to-continue`: 「続けますか／進めてよいですか／どうしますか」等、エージェント自身が
    続行の許可を求める問いは**続行**（セミオートの趣旨そのもの）。同じ文に不可逆操作が
    あれば上の 3 種が先に当たる。
- 既定上限 3→10（裁量あり 10→20）も同日（実運用で 3 は少なかった）。これは判定ではなく
  回数の変更。

## v1 — 2026-10-29（初版）

- 根拠: このMacの全 transcript の静的解析（Claude 1.8%・Codex 10.5%・opencode 6.2% が
  「つづけて」系。直前発話は「未完／次は」4 割、疑問文終わり 1%。番号付き選択肢にも
  ユーザは「つづけて」で返す）。
- ルール: 空発話→停止／疑問文で終わり直前 400 文字に人にしかできない語（権限・認証情報・
  実機・デプロイ・push・課金…）→停止／「未完・次は・残り」＋非疑問→続行／それ以外は
  判定器（Haiku）に CONTINUE・HUMAN・DONE の 1 語。判定器エラーは停止側。
- 直近の人間の指示が続行系（「改善を続けてください」等）ならその言い回しを続行文に使い、
  判定器にも「指示自体が続行要求」を渡す。
